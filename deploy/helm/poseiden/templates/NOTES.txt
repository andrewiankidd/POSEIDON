POSEIDEN {{ .Chart.AppVersion }} deployed as {{ include "poseiden.fullname" . }} ({{ .Values.ingress.type }} ingress).

1. Access it:
{{- if .Values.ingress.enabled }}
   https://{{ .Values.ingress.host }}
   (make sure that host resolves to your ingress / gateway.)
{{- else }}
   kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "poseiden.fullname" . }} 8737:{{ .Values.service.port }}
   then open http://localhost:8737
{{- end }}

2. Data: single-replica SQLite on
   {{- if .Values.persistence.enabled }} a {{ .Values.persistence.accessMode }} PVC ({{ .Values.persistence.size }}){{ else }} an emptyDir (NOT persisted - set persistence.enabled=true){{ end }} at {{ .Values.persistence.mountPath }}.

3. Auth:
{{- if .Values.auth.enabled }}
   Enforced at the ingress by oauth2-proxy (provider: {{ .Values.auth.provider }}). The
   app reads the injected X-Auth-Request-* identity headers.
  {{- if .Values.auth.tokenVerification.enabled }}
   Token verification ON: the forwarded access token is verified against the JWKS
   ({{ .Values.auth.tokenVerification.jwksUrl }}) and the owner taken from its
   verified claims - a spoofed identity header alone is rejected (fail-closed).
  {{- end }}
  {{- if and (eq .Values.auth.provider "dex") .Values.auth.dex.bundled.enabled }}
   Bundled Dex - log in with the static user(s) you configured in
   auth.dex.bundled.staticPasswords.
  {{- else if and (eq .Values.auth.provider "keycloak") .Values.auth.keycloak.bundled.enabled }}
   Bundled Keycloak (POC, embedded H2 - not for production). Admin console:
     kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "poseiden.keycloak.fullname" . }} 8080:8080
   then http://localhost:8080  (user: {{ .Values.auth.keycloak.bundled.adminUser }}). Create users in realm "{{ .Values.auth.keycloak.realm }}".
  {{- end }}
  {{- if and (eq .Values.ingress.type "istio") (not .Values.ingress.istio.externalProviderName) }}

   ⚠  ACTION REQUIRED (cluster admin, one-time): register the ext-authz provider
      "{{ include "poseiden.oauth2proxy.fullname" . }}" in istiod meshConfig.extensionProviders,
      pointing at service {{ include "poseiden.oauth2proxy.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local:80.
      Until then the AuthorizationPolicy references an unknown provider and requests fail closed.
      See the chart README ("Enterprise cluster: meshConfig registration").
  {{- end }}
  {{- if not .Values.networkPolicy.enabled }}

   ⚠  IN-CLUSTER SPOOFING RISK (networkPolicy.enabled=false). The app trusts the
      X-Auth-Request-Email header as identity. The ingress overwrites it so it
      can't be forged through the front door, but any pod that can reach the app
      Service directly can set it itself and impersonate any tenant. For a shared
      or multi-tenant cluster, set networkPolicy.enabled=true (needs an enforcing
      CNI) to restrict the app to your ingress / gateway.
  {{- end }}
{{- else }}
   ⚠  SINGLE TENANT (auth.enabled=false). With no identity headers every request
      collapses to one shared `default` owner - there is no per-user isolation.
      Fine for a dev / {{ if .Values.localhost.enabled }}localhost {{ end }}playground or a single-user self-host; for MULTIPLE
      isolated users set auth.enabled=true with a provider (see values.yaml / README).
      POSEIDEN also ships no login of its own, so gate this host at your ingress /
      mesh before exposing it.
{{- end }}
